# ONNX vs OpenVINO 추론 속도 비교

## 실험 환경

| 항목 | 내용 |
|------|------|
| 이미지 | `Pathology_new` 상위 5장 (256×256 px) |
| 프롬프트 | 이미지당 4개 셀, 셀당 5~6개 꼭짓점 포인트 (실제 클릭 좌표) |
| 반복 횟수 | 워밍업 1회 + 측정 5회 평균 |
| 하드웨어 | Intel CPU |

## 모델 정보

| 구분 | 모델 | 정밀도 | 런타임 |
|------|------|--------|--------|
| ONNX | `encoder.quantized.onnx` + `decoder.quantized.onnx` | INT8 | onnxruntime 1.20.1 |
| OpenVINO | `encoder.xml` + `decoder.xml` | FP32 | OpenVINO 2026.2.0 |

## 평균 요약

| 항목 | ONNX-INT8 (ms) | OV-FP32 (ms) | 배율 (OV/ONNX) |
|------|---------------:|-------------:|:--------------:|
| encode | 570.0 | 74.2 | **0.13× (7.7× 빠름)** |
| decode (4셀 합산) | 97.3 | 48.8 | **0.50× (2.0× 빠름)** |
| e2e | 667.3 | 123.1 | **0.18× (5.4× 빠름)** |

> 2026-06-17 `benchmark_speed.py` 재실행 결과로 갱신. (재실행 전 스크립트의 `ONNX_DIR` 경로가 `deployment/`로 잘못되어 있어 실행 자체가 안 되던 버그를 `deployment/onnx/`로 수정한 뒤 측정함.)

## 분석

- **OpenVINO FP32가 전 항목에서 ONNX INT8보다 빠름**
- encode가 전체 시간의 85~88%를 차지하며, 여기서 차이가 가장 큼 (7.2×)
- ONNX는 INT8 양자화 모델임에도 OpenVINO의 oneDNN 커널 최적화(Intel CPU 전용 fused ops)가 더 효과적
- decode는 1.9× 차이로 상대적으로 격차가 작음
- e2e 기준 OpenVINO는 **평균 125 ms**, ONNX는 **637 ms** — 실시간 interactive 추론에서 OpenVINO가 실용적
